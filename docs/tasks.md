## 通用执行规则

-   所有后续承担页面改造的 agent 在开始任务前必须完整读取并使用：
    1. `.agents/skills/frontend-design/SKILL.md`
    2. `.agents/skills/design-taste-frontend/SKILL.md`
    3. `.codex/skills/ui-ux-pro-max/SKILL.md`
-   `design-taste-frontend` 明确不以后台/数据表格为主要适用对象，因此本项目只使用其改版审计、反模板化、颜色/形状一致性和交付前检查；不得把营销页规则强行套入后台。
-   `ui-ux-pro-max` 每轮页面批次必须先运行 `--design-system` 和 `--stack vue` 检索；检索建议与 `DESIGN.md` 冲突时，以 `DESIGN.md` 和本计划为准。
-   不引入第二套 UI 组件库；Element Plus 是唯一组件系统。
-   不提交密码、Token、数据库连接串或服务器凭据。
-   每项任务完成时必须附文件清单、自动检查结果、人工验证结果和未通过项。

    -   为四个目录、18 个页面和全部操作建立 `rule_code -> permission_code -> page/action -> API` 矩阵。
    -   菜单查看、标准 CRUD 和特殊动作均使用 `docs/api-documentation.md` 的权限码。
    -   明确只读页不授予无意义的编辑按钮。
    -   保留现有 `auth/*` 规则和组件路径，不重新设计权限中心。
    -   验收：18 个页面无遗漏；每个可见按钮都有规则，每个规则都能追溯到文档接口或明确的纯前端行为。

-   [x] **T012 编写 Cochain 专用 DM8 初始化脚本**

    -   以 `E:\router\router\sql\rbac-bootstrap-dm.sql` 为参考，在本项目中创建专用 SQL。
    -   配置 bootstrap userid `196045`、project `cochain`、project super、管理组、原有 `auth/*` 菜单、18 个业务菜单、按钮和必要的 RBAC 管理 API 映射。
    -   使用幂等 `MERGE`，附执行前检查、执行后查询和失败回滚说明。
    -   不修改共享模板，不创建 `__global__`，不把凭据写入 SQL。
    -   验收：静态审查确认无 `oversia`、`flow` 或旧页面组件路径。

-   [x] **T013 确认业务 API 是否经过 RBAC enforcement**

    -   通过 RBAC 服务源码/部署拓扑核对 `rbac_api_permission_map` 的实际作用域。
    -   若业务 API 不经过 RBAC 服务，只依靠业务后端 `@PreAuthorize`，不得登记无效映射并声称完成保护。
    -   验收：菜单/按钮权限、RBAC 管理 API 映射和业务后端权限三者边界有书面结论。
    -   该任务为只读评估，不授权修改 RBAC 服务端或现有前端 RBAC 框架。

    -   验收：数据库行存在且索引查询可见；两者缺一不可。

-   [x] **T016 完成真实登录与授权验收**
    -   使用 Keycloak client `cochain-web` 和账号 `196045` 登录。

    -   验证 `auth/*` 无回归，18 个业务菜单和对应按钮规则完整返回。
