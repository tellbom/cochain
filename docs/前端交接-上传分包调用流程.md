# 前端交接：从上传分包文件开始的调用流程

> 更新日期：2026-08-18。本文可直接作为前端 Codex 的API绑定依据；若与Swagger展示冲突，以本文列出的实际Controller签名和运行时响应结构为准。

## 0. 给前端Codex的绑定约束

1. 创建独立的API客户端、请求/响应类型和业务调用函数，不要在页面组件内散落URL。
2. 普通JSON接口保留`Result<T>`包装并统一解包；成功条件是`success === true && code === 200`。
3. 所有ID使用TypeScript `string`，禁止`Number(id)`、`parseInt(id)`或数字型路由参数。
4. 上传使用`FormData`且不手工设置`multipart/form-data`请求头边界。
5. 导出接口绕过普通JSON解包，固定使用`responseType: 'blob'`和§9.3实现。
6. 业务时间按`yyyy-MM-dd HH:mm:ss`字符串处理；不要用浏览器UTC转换后再提交。
7. Token只从现有Keycloak登录态读取并写入`Authorization: Bearer <token>`，不在前端保存管理员密码或调用管理员接口。

## 1. 接口约定

- 本地基础地址：`http://{host}:8080`
- 鉴权请求头：`Authorization: Bearer <token>`
- Keycloak地址：`http://192.168.124.2:18085`
- Realm：`master`
- 前端Client ID：`cochain-web`
- 后端不校验Token的`aud`，前端无需为分包系统额外申请客户端或角色；Token缺失、签名错误、过期或issuer不是`master`时返回`401`。
- JSON请求头：`Content-Type: application/json`
- Excel上传：`multipart/form-data`，由浏览器自动生成`boundary`，不要手工固定`Content-Type`。
- 所有`id`、`batchId`、`packageId`、`supplierId`均按`String`处理，禁止转换为JavaScript`number`，避免雪花ID精度丢失。
- 业务时间字符串统一为`yyyy-MM-dd HH:mm:ss`、时区`Asia/Shanghai`；`Result.timestamp`单独使用Unix毫秒时间戳。
- 普通接口统一返回：

```json
{
  "success": true,
  "message": "",
  "code": 200,
  "data": {},
  "timestamp": 1787040000000
}
```

前端必须按`success === true && code === 200`判断成功，再读取`data`；失败时展示`message`。响应字段名是`message`，不是`msg`。

分页响应中的`data`实际只有`list`和`total`，不会回显`pageNo`、`pageSize`；前端自行保存分页请求参数。

后端需要工号时统一调用：

```java
String employeeNo = JwtTokenUtils.getEmployeeNo();
```

解析顺序为`employee_no`、`employeeNo`、`employee_number`、`employeeNumber`、`preferred_username`、`user_name`；当前`master`默认以`preferred_username`作为工号。

`operator`是批次的业务展示字段，不用于数据库审计。`CREATOR`、`UPDATER`由后端从上述JWT工号自动填充，前端不要伪造或额外提交审计字段。

## 2. 推荐调用顺序

```text
选择并校验Excel
  -> 上传Excel，取得batchId
  -> 展示成功/失败行，确认是否继续
  -> 查询导入零件（可选）
  -> 一键编排：分包 + 推荐 + 推荐结果回写
  -> 查询批次状态
  -> 查询工作包列表
  -> 查询供应商推荐明细
  -> 下载最终Excel
```

推荐页面状态机：

```text
DATA_READY -> PACKAGED -> RECOMMENDED -> COMPLETED
                    \-> PARTIAL ------> COMPLETED（允许导出，但前端应提示推荐不完整）
```

状态说明：

| 状态 | 前端含义 | 可执行操作 |
| --- | --- | --- |
| `DATA_READY` | Excel已导入，尚未分包 | 一键编排或执行分包 |
| `PACKAGED` | 已生成工作包，尚未推荐 | 执行推荐、查看工作包 |
| `RECOMMENDED` | 所有工作包推荐完整 | 查看结果、导出 |
| `PARTIAL` | 至少一个铝/钛/钢普通工作包推荐数量不足 | 查看缺口、仍可导出 |
| `COMPLETED` | 已执行最终结果导出 | 可再次下载或查看历史结果 |

## 4. 第一步：上传分包Excel

### 4.1 请求

```http
POST /api/subcontract/batch/upload
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

权限：`subcontract:batch:upload`

| 参数 | 位置 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `file` | form-data | File | 是 | `待上传分包测试数据_下料尺寸_20260814.xlsx` | 36列分包文件 |
| `aircraftModel` | form-data/query | String | 否 | `zz` | 只补全Excel中机型为空的数据行，不覆盖已有值 |
| `operator` | form-data/query | String | 否 | `张三` | 当前登录人姓名或工号 |

前端调用示例（完整封装见§9.2）：

```ts
const importResult = await uploadPackingFile(file, {
  aircraftModel: 'zz',
  operator: currentUserName,
});
const batchId = importResult.batchId;
```

### 4.2 成功返回

```json
{
  "code": 200,
  "message": "",
  "data": {
    "batchId": "2088160508777541634",
    "batchNo": "BATCH-20260814-001",
    "totalRows": 30,
    "successCount": 30,
    "errorCount": 0,
    "errors": []
  }
}
```

返回字段：

| 字段 | 类型 | 前端处理 |
| --- | --- | --- |
| `batchId` | String | 必须保存；后续所有主流程接口的路径参数 |
| `batchNo` | String | 页面展示和人工核对 |
| `totalRows` | Integer | Excel解析出的数据行数，不含表头 |
| `successCount` | Integer | 实际落库行数 |
| `errorCount` | Integer | 校验失败行数 |
| `errors[].rowNo` | Integer | Excel数据行序号，从1开始，不含表头 |
| `errors[].message` | String | 行错误原因 |

上传允许“部分成功”：只要至少一行有效，就会创建批次并返回`batchId`。建议前端规则：

- `errorCount === 0`：允许直接进入编排。
- `errorCount > 0 && successCount > 0`：展示错误表格，由用户选择继续处理有效行或修正后重新上传。
- 所有行失败、文件为空或模板无法解析：统一接口返回失败，页面不进入下一步。

常见行错误：

```text
零件图号不能为空
供应商需求数必须为正整数
下料尺寸格式错误,应为“长*宽”,例如“1200*600”
```

## 6. 第三步：执行编排

### 6.1 推荐方式：一键编排

```http
POST /api/subcontract/batch/{batchId}/run
Authorization: Bearer <token>
```

权限：`subcontract:batch:run`

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `batchId` | path | String | 是 | 上传返回的`batchId` |

该接口没有请求体。它在一个事务中依次执行：重新分包、供应商推荐、推荐供应商1—7回写。

```ts
const orchestration = await runPacking(batchId); // 完整封装见§9.2
```

成功响应：

```json
{
  "code": 200,
  "message": "供应商推荐完成，但存在数量不足：工作包zz-2608-002需推荐6家供应商，当前仅有4家具备加工能力，已推荐全部可用供应商，缺口2家",
  "data": {
    "batchId": "2088160508777541634",
    "batchNo": "BATCH-20260814-001",
    "batchStatus": "PARTIAL",
    "packageCount": 27,
    "recommendationCount": 133,
    "hasWarning": true,
    "warnings": [
      {
        "packageId": "2088160508777542001",
        "packageNo": "zz-2608-002",
        "requiredCount": 6,
        "availableCount": 4,
        "shortageCount": 2,
        "message": "工作包zz-2608-002需推荐6家供应商，当前仅有4家具备加工能力，已推荐全部可用供应商，缺口2家"
      }
    ]
  }
}
```

`batchStatus`实际结果为：

- `RECOMMENDED`：全部工作包达到推荐目标。
- `PARTIAL`：至少一个铝/钛/钢普通工作包候选供应商不足；特殊品类不按推荐数量判定该状态。

前端提醒规则：当`data.hasWarning === true`时，必须用弹窗、警告条或结果页醒目区域展示`data.warnings[].message`。此时后端已经把每个不足工作包当前全部可加工供应商写入推荐结果，前端不需要自行补选。

注意：一键编排本身不会把状态改为`COMPLETED`；只有调用最终导出接口后才会进入`COMPLETED`。

### 6.2 可选方式：分步执行

需要在分包后让用户先确认工作包时，使用以下两个接口替代一键编排。

第一步，分包：

```http
POST /api/subcontract/batch/{batchId}/package
权限: subcontract:batch:package
请求体: 无
返回: Result<PackageVO[]>
```

第二步，推荐：

```http
POST /api/subcontract/batch/{batchId}/recommend
权限: subcontract:batch:recommend
请求体: 无
返回: Result<SupplierRecommendationVO[]>
```

推荐接口必须在分包后调用，否则返回“批次下无工作包,请先执行分包”。铝/钛/钢候选不足时，`data`仍是当前全部可加工供应商数组，响应`message`包含逐包目标数、实际数和缺口，前端必须展示该提示。分包支持重跑，但重跑会清理该批次原工作包和原推荐结果并重新计算，因此按钮需要防重复点击并显示加载状态。

### 7.1 查询批次状态

```http
GET /api/subcontract/batch/{batchId}
权限: subcontract:batch:query
```

关键响应：

```json
{
  "code": 200,
  "data": {
    "id": "2088160508777541634",
    "batchNo": "BATCH-20260814-001",
    "batchStatus": "RECOMMENDED",
    "uploadFileName": "待上传分包测试数据_下料尺寸_20260814.xlsx",
    "totalPartCount": 30,
    "totalPackageCount": 27,
    "operator": "张三"
  }
}
```

### 7.2 查询工作包

```http
GET /api/work/package/page?batchId={batchId}&pageNo=1&pageSize=20
权限: work:package:page
```

推荐至少传`batchId`，否则会查询全部批次。其他可选参数：`packageNo`、`categoryId`、`partType`、`recommendationStatus`、`hasHistorySupplier`、`isSpecialCategory`。

工作包关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String | `packageId`，查询包内零件/推荐使用 |
| `packageNo` | String | 工作包编号，如`zz-2608-001` |
| `categoryId` | String | 三级品类ID |
| `supplierCountNeeded` | Integer | 原始供应商需求数 |
| `recommendCount` | Integer | 铝/钛/钢普通品类目标推荐数，一般为需求数+4；特殊品类忽略该值 |
| `partCount` | Integer | 包内零件数 |
| `partType` | String | 零件类型 |
| `maxPartLimit` | Integer | 该类型容量上限 |
| `hasHistorySupplier` | Integer | `1`有历史供应商，`0`没有 |
| `isSpecialCategory` | Integer | `1`非铝/钛/钢特殊品类，`0`铝/钛/钢普通品类 |
| `recommendationStatus` | String | `PENDING`/`RECOMMENDED`/`PARTIAL`/`FAILED` |

### 7.3 查询包内零件

```http
GET /api/part/batch-part/page?packageId={packageId}&pageNo=1&pageSize=20
权限: part:batch-part:page
```

也可用`batchId + packageNo`查询。列表按`seqNo`升序返回。

### 7.4 查询推荐结果

按批次查询：

```http
GET /api/package/supplier-recommendation/page?batchId={batchId}&pageNo=1&pageSize=50
权限: package:supplier-recommendation:page
```

按工作包查询：

```http
GET /api/package/supplier-recommendation/list?packageId={packageId}
权限: package:supplier-recommendation:query
```

可选过滤参数：`supplierId`、`supplierName`（模糊）、`recommendOrder`、`recommendSource`、`qualityLevel`、`performanceScore`。

推荐结果关键字段：

```json
{
  "id": "RECOMMENDATION_ID",
  "packageId": "PACKAGE_ID",
  "batchId": "BATCH_ID",
  "supplierId": "SUPPLIER_ID",
  "supplierName": "供应商名称",
  "recommendOrder": 1,
  "recommendSource": "HISTORY",
  "qualityLevel": "优质",
  "performanceScore": 88.50
}
```

`recommendSource`枚举：

| 值 | 含义 |
| --- | --- |
| `HISTORY` | 历史供应商优先 |
| `QUALITY_ROUND` | 优质供应商轮流选取 |
| `NORMAL_ROUND` | 普通供应商轮流选取 |
| `CATEGORY_CAPABILITY` | 铝/钛/钢排名不足时按品类加工能力补充 |
| `ALL_CATEGORY` | 特殊品类推荐全部有效关联供应商 |

特殊品类说明：材料类型不是铝、钛、钢时，后端直接返回该三级品类下所有启用且具有加工能力关联的供应商，不读取排名、不轮流补足，也不验证结果是否达到`recommendCount`。因此特殊品类即使只返回少量供应商或0家，其工作包状态仍为`RECOMMENDED`；前端不得据`recommendCount`自行改判为`PARTIAL/FAILED`。

推荐列表接口默认按记录ID倒序，不保证位次顺序。前端展示单个工作包时应按`recommendOrder`升序排序。

## 8. 第五步：下载最终结果Excel

```http
GET /api/subcontract/batch/{batchId}/export
Authorization: Bearer <token>
```

权限：`subcontract:batch:export-result`

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `batchId` | path | String | 是 | 上传返回的批次ID |

接口返回Excel二进制流，不是`Result<T>` JSON。调用时必须配置`responseType: 'blob'`。

不要直接调用`URL.createObjectURL(response.data)`；当响应被拦截器解包或后端返回JSON错误时，`response.data`不一定是`Blob`，会触发`Overload resolution failed`。请直接采用§9.3的完整实现。

导出接口执行以下动作：

1. 将每个工作包的推荐名称回写到零件的“推荐供应商1—7”。
2. 把内部`lengthValue`和`widthValue`重新合成为Excel“下料尺寸”列。
3. 生成36列结果Excel。
4. 将批次状态更新为`COMPLETED`。

## 9. 前端接口封装建议

```ts
export interface ApiResult<T> {
  success: boolean;
  message: string;
  code: number;
  data: T | null;
```

### 9.1 Axios基础客户端

下面的`getAccessToken`应连接前端现有Keycloak实例；不要把Token写死在源码中。

```ts
import axios, { type AxiosResponse } from 'axios';

const getAccessToken = (): string | undefined => keycloak.token;

export const partPackingApi = axios.create({
  baseURL: import.meta.env.VITE_PART_PACKING_API_BASE_URL ?? 'http://localhost:8080',
  timeout: 60_000,
});

partPackingApi.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

export async function unwrap<T>(
  request: Promise<AxiosResponse<ApiResult<T>>>,
): Promise<T> {
  const response = await request;
  const body = response.data;
  if (!body.success || body.code !== 200) {
    throw new Error(body.message || `接口调用失败，业务码：${body.code}`);
  }
  return body.data as T;
}
```

### 9.3 Excel导出绑定

导出接口不是`Result<T>`，必须单独处理。以下实现保证传给`URL.createObjectURL`的一定是`Blob`，并能读取后端以JSON返回的错误信息。

```ts
function parseDownloadFileName(disposition?: string): string | undefined {
  const utf8 = disposition?.match(/filename\*=UTF-8''([^;]+)/i)?.[1];
  if (utf8) return decodeURIComponent(utf8);
  return disposition?.match(/filename="?([^";]+)"?/i)?.[1];
}

export async function downloadPackingResult(batchId: string): Promise<void> {
  const response = await partPackingApi.get<Blob>(packingEndpoints.exportResult(batchId), {
    responseType: 'blob',
  });
  const contentType = String(response.headers['content-type'] ?? '');
  const blob = response.data instanceof Blob
    ? response.data
    : new Blob([response.data], { type: contentType });

  if (contentType.includes('application/json') || blob.type.includes('application/json')) {
    const error = JSON.parse(await blob.text()) as ApiResult<unknown>;
    throw new Error(error.message || '导出失败');
  }

  const fileName = parseDownloadFileName(response.headers['content-disposition'])
    ?? `供应商推荐清单_${batchId}.xlsx`;
  const blobUrl = URL.createObjectURL(blob);
  try {
    const link = document.createElement('a');
    link.href = blobUrl;
    link.download = fileName;
    document.body.appendChild(link);
    link.click();
    link.remove();
  } finally {
    URL.revokeObjectURL(blobUrl);
  }
}
```

页面按钮防护建议：

- 上传、编排和导出期间禁用对应按钮，避免重复提交。
- 上传成功后立即把`batchId`写入路由参数或页面状态；刷新页面时用批次详情接口恢复状态。
- `PARTIAL`不能显示成“全部推荐成功”，应显示“推荐不完整”，并允许进入工作包列表查看`PARTIAL/FAILED`包。
- `hasWarning=true`时必须展示`warnings[].message`；提示用户系统已推荐当前全部可加工供应商，但仍有数量缺口。
- 导出失败时后端可能返回JSON错误而不是Excel，前端下载逻辑应先检查响应头或尝试解析错误Blob。
- 用户重新上传修正后的Excel会产生新批次，前端应切换到新的`batchId`，不要继续使用旧批次ID。
